# Журнал решений FlashTune

Этот файл нужен, чтобы потом было понятно, почему проект сделан именно так.

## WordPress вместо отдельной самописной CMS

Причина:
- удобная админка;
- много готовых интеграций;
- проще поддержка;
- WooCommerce;
- SEO;
- легко добавлять страницы и статьи.

## WooCommerce для заказов

Причина:
не нужно самостоятельно писать корзину, заказы, пользователей, оплату и статусы.

WooCommerce используется как коммерческий слой, а каталог прошивок при необходимости можно сделать отдельно.

## Кастомная тема

Причина:
обычная готовая тема не даст нужный визуальный стиль.

Нужен собственный интерфейс:
- anime;
- cyberpunk;
- street racing;
- неоновый каталог.

## GitHub Pages только для preview

Причина:
GitHub Pages не запускает PHP и WordPress.

Поэтому там показываем только внешний вид сайта.

## Файлы на VPS на старте

Причина:
- проще;
- дешевле;
- не нужен отдельный S3;
- небольшие BIN-файлы не создают большой нагрузки сами по себе.

Важно: файлы должны лежать в закрытой папке.

Если объём или трафик вырастут — переносим в S3.

## Не создавать 10 000–50 000 записей вручную

Причина:
это невозможно нормально поддерживать.

Каталог должен создаваться массовым импортом.

## Два сценария продажи

### Готовая калибровка
Есть точное совпадение ECU/HW/SW — пользователь покупает готовое решение.

### Индивидуальный заказ
Готового решения нет — пользователь загружает оригинальный файл.

## «Умный подбор» вместо фальшивой генерации ИИ

На первой версии сайт реально ищет совместимость в базе.

Не нужно утверждать, что нейросеть создаёт уникальный файл, если она этого не делает.

Позже можно добавить настоящие AI-функции.
